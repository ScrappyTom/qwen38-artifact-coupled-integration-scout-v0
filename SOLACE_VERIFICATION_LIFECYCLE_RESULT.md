## Bottom line

Retaining the frozen semantic register through verification did not earn positive
value in this cell.

Both arms began from the same exact strong-partial Solace artifact, latest
construction effect, source catalog, check/patch/read surface, and external
history. Both immediately ran the current candidate-bound check, read the same
four defect-relevant sources, and produced substantive repairs. The register arm
used one broad patch to make every frozen concept gate pass. The artifact-only
arm used four patches and four checks to reach the same mechanical state.

Neither arm completed. Both stopped when verification chronology and the latest
candidate effect could no longer fit and no eligible exact result body could
restore feasibility. Neither final effect crossed another actor boundary, no
final current recheck occurred, and neither arm submitted.

Direct source-bound review also reverses the tempting mechanical interpretation
that both artifacts were one heading repair from completion. The concept checker
does not validate the relationships among required values:

* A1 changed CIPHER's current forty-eight-sample set into an unsupported
  forty-eight-samples-per-round rule and weakened BASTION's positive all-node
  restoration gate into a low-pressure condition.
* A0 repaired those requirements faithfully but retained a donor sentence that
  dimensionally compares pump flow capacity with a 6.5 MW power value.

Both final artifacts are therefore `strong_partial`, `not_ready`, and not useful
completions.

The supported systems claim is:

> The frozen provenance register remained behaviorally useful as repair
> scaffolding: with BASTION/CIPHER already externalized, A1 still repaired four
> source domains in one action. But carrying the register imposed 6,646 tokens
> of initial resident cost, shortened the reachable verification loop from ten
> calls to four, prevented the first patch effect from reaching a recheck, and
> did not protect relationship fidelity. A0's exact artifact plus current check
> and targeted source reads produced slower but semantically closer repair.
> Verification then failed for both arms because append-only check/effect/action
> state became the next unrelievable burden.

This is local evidence for demoting construction scaffolding at verification,
not proof that semantic residue lacks value during acquisition or construction.

## System-level learning

### 1. Semantic scaffolding has a lifecycle

Solace construction showed positive local value from the register-plus-artifact
configuration. This verification continuation shows that the same resident
stock can become a liability after the artifact has absorbed much of its useful
meaning.

The emerging policy is phase-conditional rather than representation-global:

```text
acquisition / early construction
    temporary provenance-bound scaffold may organize evidence
construction
    exact incremental artifact absorbs cumulative meaning
verification
    scaffold should be demoted unless it earns current marginal value
    exact artifact + current check + targeted exact evidence dominate
```

This is a local hypothesis, not a universal demotion rule.

### 2. Verification state needs replacement semantics

A0 proves that removing the register is not sufficient. Its sequence accumulated:

```text
check
+ source observations
+ patch effect
+ check
+ patch effect
+ check
+ patch effect
+ check
+ patch effect
```

Old checks became stale after every patch, yet their wrappers and intervening
chronology remained model-facing until first-fit could externalize some exact
bodies. Eventually no eligible body remained even though the useful current
state was small:

* exact current artifact;
* latest admitted effect;
* one current or pending check state;
* exact handles to prior evidence and history.

Verification therefore needs an explicit lifecycle operation that replaces
stale check/effect chronology with a bounded mechanical current-state frame.
This is not semantic summarization: candidate hashes, effect bindings, check
currency, and exact history handles are host-known facts.

### 3. Actionable feedback quality is part of the loop

The checker said only `exact ordered level-two headings`. It did not return the
expected eight headings beside the observed eleven. The actor responded with a
case-only rewrite and spent its last feasible action without addressing the
structural defect.

A future validator projection should expose frozen expected/observed structure
and relationship-aware criterion failures. This is task-derived feedback, not a
host-authored repair.

### 4. Smaller token cost is not automatically better

A1 used fewer calls and tokens because the register brought the terminal pressure
forward. It also made a broader first repair. Those facts pull in opposite
directions. The relevant outcome is the complete lifecycle: effect uptake,
current recheck, semantic fidelity, repair, readiness, and closure. Neither arm
completed that lifecycle.

to a fresh world:

1. use temporary provenance scaffolding during pressured evidence acquisition

2. accumulate interpretation in an exact incremental artifact;
3. prospectively demote the scaffold when entering verification;
4. replace stale check/effect chronology with a bounded, mechanically derived
   current verification frame;
5. expose task-derived expected/observed validator findings;
6. continue through repair, current recheck, independent readiness, and closure.

The comparator should retain the construction scaffold and ordinary append-only
verification history. This compares two complete lifecycle allocations, not an
isolated note field. A successful transfer would support the emerging division
of labor; a failure would identify the first new interaction boundary.
