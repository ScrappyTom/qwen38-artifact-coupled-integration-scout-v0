# Capability terrain map

Date: 2026-08-24

Status: updated through the first pressure-active interaction; not a prevalence estimate or architecture

## Purpose and limits

This map reorganizes the existing evidence by information-processing function
rather than by mechanism name. It is deliberately small. Its purpose is to
show what has actually been observed, what recurs across independent worlds,
and where the program remains too narrow to justify optimization.

The source of truth for claim scope remains `EVIDENCE_LEDGER.md`. Heterogeneous
tasks, models, interfaces, horizons, and evaluators are not pooled. A mark of
recurrence means a broadly similar functional boundary appeared in independent
worlds; it is not a causal estimate or architecture promotion.

Evidence imported from `bounded-context-harness-effects` uses Qwen 3.6 27B,
mostly rule-dense JavaScript coding tasks, a larger context regime, and
different action interfaces. It supplies cross-profile functional analogues
and within-program task recurrence. It is not pooled replication of the
Qwen3.8 large-world studies and does not transfer treatment effects,
prevalence estimates, or model-specific capability claims.

## What the map says now

Five conclusions are now comparatively broad:

1. Exact custody and prospective capacity safety are reusable mechanical
   substrate functions.
2. Operability does not establish relationship assembly, action formation,
   effect uptake, repair, or correct closure.
3. Semantic and control packages are behaviorally active enough to create risk;
   their value depends on configuration and downstream artifact quality.
4. Action expression and admission can dominate long before context pressure,
   and can prevent downstream capability from becoming observable.
5. Successful mutation and current-check uptake do not establish complete
   requirement binding or correct readiness.

The largest coverage gaps are not another eviction choice. They are:

- how dispersed evidence becomes a durable relationship or claim and then
  actually constrains action;
- whether incremental exact work can carry cognition across information
  turnover;
- which conditions let the actor stop acquisition, organize work, and express
  a legal action;
- how effects and checks remain current and discriminating across continuation;
- whether bounded subwork can be reintegrated; and
- how readiness is discriminated without a closure-biased cue.

These rows are not a component backlog. A future experiment should code several
rows along one complete trajectory and ask how the active information
functions change one another. E37 is specifically a low-pressure reference: it
cannot adjudicate context×persistence×work-product interaction because those
operations never co-activated.

## Routing constraints after the first discovery wave

Do not rerun a function already covered merely under a new label. In
particular, the next wave should not contain another:

- same-boundary first-fit horizon;
- exact directory/focus placement;
- frontier schema repair;
- one-source digest format tweak;
- generic progress/readiness message; or
- one-shot workspace manager prompt.

The first source-residue × incremental-work candidate failed its final
apparatus gate and is closed under E38's stopping rule. E39/E40 then measured
bounded ingress × semantic-work sidecar under live pressure. Both functions
activated, but exact task-artifact accumulation did not: semantic grounding
contracted, batch geometry accelerated reentry use, and no candidate changed.

The next checkpoint exposes semantic persistence × exact incremental artifact
state × version-bound feedback inside one full ingress/effect/repair/closure
contrast. It explicitly does not study a note, patch surface, or checker in
isolation. `NEXT_SYSTEM_INTERACTION_ARTIFACT_COUPLING.md` defines the Stage 0
obligations; `SYSTEM_INTERACTION_EXPLORATION.md` defines the non-isolation rule;
and `STRUCTURED_EXPLORATION_ROADMAP.md` requires owner review before measured
inference and again before confirmation.
