# What we learned: the full bounded-context experimental sequence

Date: 2026-08-24

Status: evidence-bounded program narrative through E40; artifact-coupling
systems Stage 0 selected, no successor GPU run authorized

## What we learned

The central result is not that one memory format won. The experiments separated
what initially looked like one “context is full” problem into several different
problems with different owners and failure modes.

### 1. Exact custody and capacity control are the strongest layer

The most repeatable successes were mechanical:

- preserve authoritative objects and events outside the prompt;
- bind them to exact identities, versions, and hashes;
- expose exact reopen operations;
- calculate the real prompt under the locked tokenizer and template;
- reserve response and control capacity prospectively; and
- replace only enough previously delivered, exact-backed material to admit the
  next result.

This substrate repeatedly kept the actor physically operable. Exact reopening
was not merely a formal guarantee: Qwen requested and used demoted objects many
times.

### 2. Physical opportunity is not task progress

Minimum relief solved authentic result-delivery failures. Extending the same
policy to 12 new decisions per seed prevented capacity termination throughout
the authorized horizon. It still produced 24 acquisition decisions, no
mutation, and no submission.

The program therefore learned to keep these outcomes separate:

```text
prompt can fit
result crosses a model boundary
model makes a decision
action is admitted and changes the candidate
effect crosses a later model boundary
artifact becomes correct
closure is appropriate
```

Success at one line does not imply success at the next.

### 3. Recoverability is not co-residency

Receipts and handles created a reliable filing cabinet. They did not create a
stable working desk. During the long recurrence study, Qwen repeatedly faulted
old evidence back in. Seed 42 ultimately repeated the same three-document
reopen sequence twice.

The exact late-history audit showed why that loop could be rational. Restoring
all four governing documents inside the accumulated histories required 23,405
and 22,562 prompt tokens—2,413 and 1,570 over the allowance. In a fresh packet,
the same four documents required only 14,173 tokens and left 6,819 tokens of
headroom. The evidence fit; the path used to acquire it did not.

### 4. Chronology has a useful lifecycle, not permanent residency rights

Demoting large result bodies worked until actions, receipts, reopens, errors,
and access history themselves became the major cost. Even reducing every
remaining eligible full body to a receipt could not restore the useful set
inside the late transcript.

This was a failure migration:

```text
large exact bodies fill context
    -> body demotion restores capacity
    -> repeated work grows chronology
    -> chronology prevents useful co-residency
    -> fresh exact phase becomes economically plausible
```

Append-only chronology, append-only receipts, append-only notes, and
append-only digests all fail eventually. Sustainable context must replace,
recompose, or decompose state.

### 5. Fresh exact reentry can create action, but it is conditional

Removing accumulated acquisition history and rebuilding an exact construction
packet produced an admitted, grounded mutation in one of two seeds. This
disconfirmed the strong claim that the full acquisition transcript is always
needed for construction.

It did not create a stable construction phase. The other seed requested an
omitted target region, and both continuations soon reached another delivery
boundary. Older code and research studies also showed mixed economics across
domains. Fresh reentry is an earned conditional operation, not a universal
winner.

### 6. Better exact placement did not produce a stable working set

The program successively tried:

- exact current-state recomposition;
- an explicit exact-workspace directory;
- recent placement of one model-requested span;
- accumulation of two model-requested spans;
- separate exact update-type slots; and
- optional and dedicated model-managed residency.

The recurring outcome was not random corruption. Demand moved:

```text
resident bytes requested again
    -> identify them explicitly
    -> a broader resident span is requested
    -> place requested span recently
    -> complementary resident span is requested
    -> accumulate both spans
    -> another span is requested or one focus repeats
```

This closes small host-selected layout variations at these endpoints. It does
not prove that every exact working-set representation fails.

### 7. The actor's actual access was a better demand signal than advance cache prediction

Passive `OPEN`/`PIN`/`RELEASE` controls were ignored. A later dedicated
maintenance mode made the selection task fully reachable, but both managers
released far more than required and both ordinary actors immediately requested
the same released source.

The result distinguishes reachability from allocator quality. It supports a
conservative ownership split:

- the host owns hard safety, exact custody, relief amount, and reversibility;
- the actor reveals demand through ordinary reads and reopens; and
- model-predicted future residency is not the current default policy.

### 8. Semantic representations can be active and economically harmful

A 218-token source digest was faithful enough to affect behavior. Its full
package added 720 prompt tokens and had cost 7,121 serialized tokens to
produce. Instead of eliminating the historical 8,063-byte source reopen, it
caused a 5,299-byte paired-audit reopen and then the original source reopen one
call later.

The digest acted as a complement to exact evidence in that configuration, not
a substitute. Semantic fidelity, behavioral salience, and downstream utility
are separate properties.

### 9. Control/progress information has high leverage and high closure risk

A 169-token progress state changed an exact repeated read into immediate
submission. That initially looked like the strongest semantic result. Exact
candidate-hash reconciliation showed that the submitted artifact was already a
known strong partial with two unresolved requirement groups.

The raw causal effect survived the correction; the utility conclusion reversed.
The package was an effective behavioral actuator and a failed readiness
discriminator. Model-authored progress state cannot authorize its own closure.

### 10. Semantic transport failures are not semantic-utility results

Freeform notes exceeded their token budgets. A structured frontier produced
bounded JSON but clipped semantic fields and an exact handle. A closure-safe
repair produced complete individual phrases and handles, yet the full objects
still length-terminated; llama.cpp's generated grammar omitted the declared
string-length constraints.

Those experiments qualified interfaces. They did not show that semantic
continuity itself is useless, because no actor received a fully qualified
frontier.

### 11. Artifact evaluation is part of information economics

H05 exposed an investigator error rather than a model or replay error. A coarse
13/13 review conflicted with an earlier exact-hash strong-partial adjudication.
The correction left all raw calls, actions, seals, and replay intact while
reversing the economic conclusion.

The program consequently added an external evaluation ledger keyed by exact
candidate/tree, task, rubric/evaluator, evidence manifest, criteria, readiness,
blockers, and judgment provenance. Fewer calls or earlier submission are not
benefits when the artifact is not independently ready.

### 12. Context management is a path-dependent policy problem

No object has permanent context-independent value. Value changes with phase,
candidate state, co-resident evidence, remaining capacity, recent actions,
cache state, and the demand induced by the intervention itself.

The sequence repeatedly observed feedback:

```text
free capacity          -> more acquisition
demote old evidence    -> exact reopen
add a directory        -> demand moves within resident bytes
move requested bytes   -> complementary bytes become wanted
add a digest           -> related evidence becomes wanted
add progress state     -> closure becomes more likely
```

The optimization target is cumulative useful work and artifact quality under
bounded resources and semantic risk—not minimum tokens, maximum eviction, zero
reopens, or fast submission.

## Program scale and experimental discipline

The original parent bank contained 42 exactly replayed model requests. Through
E40, 32 successor stages represent another 400 runner-qualified model/provider
calls and 4,942,404 serialized tokens. This includes apparatus qualifications,
the 71-call whole-method scout, the 54-call pressure-qualified study, the
39-call breadth tranche, the 12-call closed interaction qualification, the
two-call ingress-action qualification, and E40's 138 provider calls. Zero-call
eligibility, capacity, reconciliation, and cross-study audits remain in the
stage ledger but add no calls or tokens. The whole-method scout's
replay-ineligible cell remains included as actual execution cost but not as
qualified primary evidence. The pressure-scout total counts seed 43 and seed
314159 once each and excludes the consumed backend generation from its aborted
v0 launch because it was not runner-qualified.

Successor studies used one-attempt, zero-retry rules, frozen model/runtime
profiles, exact prompt accounting, sealed raw records, replay, direct transcript
audit, and explicit stop conditions. Historical capacity-censored controls were
not fabricated into model behavior.

Those totals describe research cost, not an efficiency score. The experiments
reuse related boundaries and differ in call horizon and causal question; they
must not be pooled as independent task replications.

## The sequence in detail

### Phase 0 — the parent navigation result

The donor experiment compared ordinary large-world access (`C0`) with a
structural-region representation (`S1`) across two seeds.

- C0 reconstructed all 970 target lines but acquired only 1/4 governing
  sources in each seed.
- S1 read 27.2% and 33.5% of the target and acquired all 4/4 governing sources.
- All four trajectories reached the same frozen context-capacity boundary
  before mutation, checking, or submission.
- Parent custody reported 42/42 exact request replay, integration verification,
  and eight study tests passing.

This established that structural addressability materially changed acquisition
without establishing complete local operability. It created the first causal
question: did the useful structural representation become too expensive to
keep resident after acquisition?

### Phase 1 — structural-outline demotion

#### 1. Independent standalone audit and continuation

The first standalone repository imported 203 exact donor objects totaling
4,455,195 bytes and preserved donor provenance. Full-outline KEEP packets were
mechanically infeasible:

| Seed | Full outline | Headroom after 4,096 reserve | Demoted packet | Headroom | Net recovery |
|---:|---:|---:|---:|---:|---:|
| 42 | 21,386 | -394 | 17,715 | +3,277 | 3,671 |
| 314159 | 22,037 | -1,045 | 18,366 | +2,626 | 3,671 |

Four continuation calls were observed. Seed 42 reopened outline page 1 and then
requested page 2. Seed 314159 read R032 and then requested outline page 1. The
second requested results could not be delivered; neither candidate changed.

The physical result was positive, and exact recovery was behaviorally usable.
The later strict causal interpretation was ineligible: the immediately
preceding target result had not crossed a parent model decision boundary and
was first delivered in the DEMOTE packet. The treatment therefore combined
demotion with delivery of one pending observation.

Evidence: [sealed audit](https://github.com/ScrappyTom/qwen38-structural-outline-demotion-v0/commit/76dd220d5217f6147c98b00fd1a783782eaf404f).

#### 2. Strict post-delivery eligibility audit

A new offline repository searched for an authentic boundary where the complete
prior state was already model-visible and the full outline was still resident.
Neither parent seed qualified, and every later same-world request already used
a nonresident outline. The correct result was `no_eligible_fork`; zero GPU calls
were made.

This was an early governance lesson: do not repair history after the fact to
make a cleaner experiment exist.

Evidence: [eligibility result](https://github.com/ScrappyTom/qwen38-structural-outline-demotion-post-delivery-v1/commit/b9099b3a2559ea29846874beac3991eab363e3f4).

### Phase 2 — context reduction at the real pressure boundary

#### 3. Minimum versus aggressive mechanical reduction

The question broadened from “drop the outline” to “reduce prior context enough
to preserve a useful decision and absorb its result.” Historical controls were
the exact Prompt N decisions already observed; the infeasible Prompt N+1
packets were physical controls, not new model responses.

The minimal policy replaced the oldest exact-backed result bodies until the
blocked result fit. The aggressive policy kept only the two most recent exact
results.

| Seed/policy | Results replaced | Tokens removed | First decision | Blocked result delivered | Next decision |
|---|---:|---:|---|---|---|
| 42/minimal | 2 | 548 | exact historical lines 1–6 read | yes | R030 |
| 314159/minimal | 2 | 1,440 | exact historical R031 read | yes | R032 |
| 42/aggressive | 8 | 9,236 | access to demoted old source | stopped by equivalence gate | — |
| 314159/aggressive | 6 | 6,956 | exact reopen of demoted old source | stopped by equivalence gate | — |

Six calls consumed 105,381 serialized tokens. The minimal treatment preserved
the exact useful decision and solved result delivery in both seeds. Aggressive
reduction changed both decisions toward the material it had removed. No actor
mutated.

This was the first clean local support for pressure-triggered, minimum-necessary
demotion of exact-backed observations.

Evidence: [pressure-boundary result](https://github.com/ScrappyTom/qwen38-context-reduction-pressure-boundary-v0/commit/ab0e21b201d04521a43f83c223a364bca35a7b86).

#### 4. Short recurrent reduction

The same rule was then applied recurrently for three decisions per seed. It
resolved two starting and four post-call pressure events. Nine substitutions
recovered 12,597 lifecycle tokens, and each seed received three exact results
across model boundaries.

All six actions were acquisitions: four exact reopens and two target reads.
There was no mutation or submission. Only 6.56% of prompt tokens were reported
cached, exposing the prefill cost of rewriting older prompt prefixes.

This established recurrence as a mechanical capability, not a productive
working-set policy.

Evidence: [recurrent result](https://github.com/ScrappyTom/qwen38-recurrent-context-reduction-v0/commit/9a42b85b4d9fd25bd873d45c08a403c2ca1ff96e).

#### 5. Twelve-decision recurrent horizon

The horizon expanded to 12 calls per seed. The host resolved two starting and
17 later pressure events, performed 30 substitutions, and recovered 44,491
cumulative lifecycle tokens. All 24 predecessor-pending and measured results
scheduled for another authorized call crossed a model boundary.

Behavior did not converge:

- 24/24 decisions were acquisitions;
- 15 were exact reopens;
- no candidate changed or submitted;
- seed 42 repeated an exact three-document cycle on calls 7–12; and
- seed 314159 shifted from novel target reads toward repeated document reopens.

The frozen formal thrash detector missed seed 42 because it assumed at most two
distinct keys in a four-decision window. The report correctly retained the
formal negative and added the direct period-three churn observation. Seed
314159 also lost one useful decision to a defective continuation-cursor
contract, then recovered with explicit ranges.

Evidence: [long-horizon result](https://github.com/ScrappyTom/qwen38-recurrent-context-reduction-horizon-v0/commit/f52642ec85efdc8f7196515503a0312af7c38d78).

#### 6. Offline construction-set counterfactual

Direct reconstruction then tested whether better eviction ordering could make
the useful evidence coexist inside the late histories.

| Packet | Seed 42 | Seed 314159 |
|---|---:|---:|
| Restore four governing documents in late history | 23,405 / -2,413 | 22,562 / -1,570 |
| Minimize all remaining old bodies, then restore four | 23,405 / -2,413 | 22,562 / -1,570 |
| Fresh packet with the four documents | 14,173 / +6,819 | 14,173 / +6,819 |
| Fresh four documents + R031–R033 | 18,546 / +2,446 | 18,546 / +2,446 |

The complete R030–R033 tail missed by only 69 tokens under ordinary
serialization. The relevant world was not inherently too large; accumulated
history prevented the working set from co-residing.

Evidence: [counterfactual audit](https://github.com/ScrappyTom/qwen38-recurrent-context-reduction-horizon-v0/commit/daa5978f817bf21189870e7306eb19e235421424).

### Phase 3 — exact phase reentry and recurrent current state

#### 7. Chronology-free construction reentry

Both fresh packets preserved the exact task, full outline, four governing
documents, unchanged candidate, and R031–R033. Historical late packets were
5,559 and 4,681 tokens over allowance; the fresh packets were 18,443 tokens and
left 2,549 tokens of headroom.

Both seeds first attempted an oversized whole-target read and then read lines
1–33. Seed 42 subsequently requested resident R033 and produced an admitted
3,642-byte insertion. The effect could not enter another call. Seed 314159
requested the omitted R030; that result also could not enter another call.

Seven calls cost 134,214 serialized tokens. One of two seeds mutated; neither
submitted. Direct review classified the changed artifact as strong partial,
with an imprecise reopen-timing statement and omitted replay-adapter correction.

Evidence: [exact-reentry result](https://github.com/ScrappyTom/qwen38-exact-construction-reentry-v0/commit/68a4b0b04c4557dcc459b42822e804f241565757).

#### 8. Recurrent exact-current-state replacement

This study replaced the resident construction history with a deterministic
standing set plus one latest-update slot. It tested two different update types:
an inherited R030 observation and an inherited patch effect.

Both inherited updates reached call 1, and each case carried at least one later
result through another recomposition. That was a local mechanical positive.
The representation was behaviorally unstable:

- observation case: `opening → R033 → opening → R030 → opening → R033`;
- effect case: whole-target rejection, resident R033, then a resident candidate
  suffix read whose duplicate result still overflowed; and
- the single latest-update slot displaced recent observations and effects.

Nine calls cost 179,658 serialized tokens. There was no new mutation or
submission.

Evidence: [recurrent-state result](https://github.com/ScrappyTom/qwen38-recurrent-exact-state-recomposition-v0/commit/c22cff99a0a1111215940c478db50e5762f1c5d3).

### Phase 4 — semantic continuity and exact-state legibility

#### 9. One-shot bounded freeform note

One maintenance call length-terminated mid-JSON at 384 completion tokens. The
other produced a valid 234-token note, but its actor immediately requested
resident R031; the result could not fit even after recomposition. Only three
calls ran, no candidate changed, and the predeclared behavioral comparison was
not evaluable.

This was an interface/capacity result, not a negative utility test of bounded
notes.

Evidence: [bounded-note result](https://github.com/ScrappyTom/qwen38-bounded-freeform-note-v0/commit/46f50817e11d1b990cbf906e9af0f74a15740137).

#### 10. Raw-text note expression qualification

Removing JSON did not enforce the 320-token note budget. Both outputs consumed
all 512 completion tokens, length-terminated, and were rejected. No actor calls
occurred. Grounded-looking content did not override mechanical failure.

Evidence: [note-expression result](https://github.com/ScrappyTom/qwen38-bounded-note-expression-qualification-v0/commit/5d86bf237201169b80b02e2fedcfdb4fe7ab94b1).

#### 11. Compact exact-workspace directory

A 117–118-token directory explicitly identified current object identities,
candidate coverage, and region residency. Both actors still requested resident
bytes: one repeated R033 and the other broadened from R033 to resident
R032+R033. Two calls cost 40,766 serialized tokens.

The directory may have changed one decision, but it did not make current bytes
functionally consumed.

Evidence: [directory result](https://github.com/ScrappyTom/qwen38-exact-workspace-directory-v0/commit/801c1bf3d9daa8739629df86bf260d4ad08e3311).

#### 12. Model-selected exact focus relocation

The requested spans were moved into recent exact focus objects without
duplication, recovering 1,988 and 1,392 prompt tokens versus infeasible ordinary
delivery. Both next decisions shifted to complementary or adjacent resident
bytes. Neither actor mutated.

Evidence: [focus result](https://github.com/ScrappyTom/qwen38-exact-focus-relocation-v0/commit/1fc4bccadab37de5ab051e60248df6ed3353b4b3).

#### 13. Accumulated two-span exact focus

Both second focus reads were delivered exactly and remained operable. The
observation actor expanded to genuinely nonresident R028–R029; the effect actor
immediately repeated its just-delivered second focus. The frozen stop rule
closed placement-only focus tuning after these two calls.

Evidence: [accumulated-focus result](https://github.com/ScrappyTom/qwen38-accumulated-exact-focus-v0/commit/6bed7b208174646b803405fdce1a83a9432fba88).

#### 14. Structured-frontier expression

A light JSON schema produced normally stopped 209- and 277-token objects where
raw notes had length-ended. Direct audit found six of eight prose fields clipped
and one truncated handle. Mechanical closure had been purchased by semantic
truncation. No actor saw the outputs.

Evidence: [frontier-expression result](https://github.com/ScrappyTom/qwen38-bounded-frontier-expression-qualification-v0/commit/3cf5ab005128b95c7af9f24d7d018eab548e6b98).

#### 15. Closure-safe frontier expression

The repair required complete punctuated values and enumerated exact handles.
All returned prose values and handles were complete, but neither full object
qualified: both consumed all 512 completion tokens; one omitted a field, and
one exceeded 320 tokens and used wrong keys. The live generated grammar omitted
declared string-length limits. No actor call ran, and the schema-tuning branch
closed.

Evidence: [closure-safe result](https://github.com/ScrappyTom/qwen38-closed-frontier-expression-qualification-v0/commit/cde5d344f81ae3af6bc5e4c3838454b7b9a0d758).

#### 16. Exact causal-slot eligibility

An offline audit tested the proposed “one latest observation plus one latest
effect” rule. One donor case had observation→observation displacement; the
other had effect→observation displacement. The rule changed only the second and
failed the two-case parity gate. Zero GPU calls ran.

The one-case complete effect+observation treatment was then measured offline at
21,113 prompt tokens, 121 over allowance. Minimal wrapper variants still missed
by 23–35 tokens. Making it fit required another content change, so the study
stopped before inference.

Evidence: [eligibility audit](audits/H08_EXACT_CAUSAL_FRONTIER_ELIGIBILITY.md)
and [capacity result](https://github.com/ScrappyTom/qwen38-cross-type-update-residency-v0/commit/7911cd88f82871e9176098e46913298b9cd28fa9).

### Phase 5 — model ownership and source semantics

#### 17. Passive model-managed exact residency

Qwen received six resident objects, an external effect, a budget, and optional
`OPEN`/`RELEASE`/`PIN` actions. It began with only 409 tokens of usable
headroom. It first attempted an oversized whole-file read, then requested
resident R031. After the rejection receipt and pending result, the compact
management packet itself was 45 tokens too large to send.

No residency action occurred. Two calls cost 41,552 serialized tokens. This
showed both a local behavioral failure and a control-plane race: the interface
could become unreachable before management occurred.

Evidence: [passive-residency result](https://github.com/ScrappyTom/qwen38-model-managed-exact-residency-v0/commit/bac9f52b38da0bccfeb65ae57b513e758f9e91db).

#### 18. Source-bound digest production

A simple four-heading text interface produced a complete 190-token digest of an
8,063-byte source with no material reversal. The actor stage was correctly
blocked because two frozen fidelity requirements referred to facts absent from
the source and prompt. Requiring them would reward fabrication.

A second seed produced a complete 218-token digest under a repaired,
source-located rubric. It passed 5/6 requirements and omitted no-candidate-change
and no-check details. The strict actor gate remained closed. These two calls
established bounded expression, not utility.

Evidence: [first digest](https://github.com/ScrappyTom/qwen38-source-bound-semantic-digest-v0/commit/014494d9ac0fe349a1cfef6dfd64262c356c0b14)
and [prospective qualification](https://github.com/ScrappyTom/qwen38-source-digest-actor-utility-v0/commit/d9336f5681ecffb8d322802c01ebaf8bb480f750).

#### 19. Deliberately lossy digest utility

Rather than tuning the 5/6 digest, the next study accepted the known,
noncontradictory loss and tested whether the package improved actual demand.
Historically the actor immediately reopened the 8,063-byte RESULTS source. With
the digest package, it reopened a related 5,299-byte audit, received it, and
then reopened the original source.

The 218-token semantic payload cost 720 resident prompt tokens because 502 were
carrier/template overhead. Production had cost 7,121 tokens. The two actor
calls added 41,036 tokens and recovered 13,362 raw source bytes without
mutation or artifact change.

This was a clean local economic negative even though the package was
behaviorally active.

Evidence: [lossy-digest result](https://github.com/ScrappyTom/qwen38-lossy-source-digest-utility-v0/commit/0081896cd5914acb14a155eb41342ffd3e788957).

#### 20. Bounded progress-state utility

At a stable-evidence boundary, a contemporaneous control repeated the exact
resident-focus read. A maintenance call generated a grounded 169-token state in
a 464-token package. The treated actor submitted immediately.

The three calls cost 59,617 serialized tokens. The initial report classified
the artifact as complete. Exact candidate reconciliation then found the same
bytes had already been judged strong partial: 10 substantive groups met and two
partial. The package caused premature closure without changing the candidate.

This was the sequence's most important interpretive correction. Behavioral
leverage remained real; useful closure did not.

Evidence: [corrected H05 result](https://github.com/ScrappyTom/qwen38-bounded-progress-state-utility-v0/commit/a3422cca49cb882ec252ba84903b856ba3cafc24)
and [reconciliation](audits/H05_ARTIFACT_DISPOSITION_RECONCILIATION.md).

### Phase 6 — governance and prior-program reconciliation

#### 21. Close-transfer eligibility

The desired next test was ready-versus-not-ready discrimination under the same
stable-evidence/no-progress phenotype. Offline donor search found no authentic
matching ready and defect-bearing cells. Older false-closure code banks operated
at a different submission/verification boundary. The transfer correctly
stopped with zero GPU calls.

Evidence: [eligibility audit](audits/H05_CLOSE_TRANSFER_ELIGIBILITY.md).

#### 22. Candidate-bound adjudication consistency

The program converted the H05 error into an append-only evaluation ledger. It
preserved four navigation-candidate judgments, marked the coarse 13/13 review
superseded, and treated the three active strong-partial records as one semantic
judgment lineage rather than three independent votes.

The hardened audit read 150 JSON objects directly from the pinned older Git
commit, found 60 scored occurrences covering 22 candidate/task groups, and
found zero score conflicts. This was a custody/consistency result, not proof
that every rubric was correct.

Evidence: [adjudication audit](audits/ARTIFACT_ADJUDICATION_CONSISTENCY_AUDIT.md).

#### 23. Prior-program overlap audit

Thirteen exact older result objects showed that several supposedly new branches
already had material evidence:

- complete exact verification reliably exposed false closure and activated
  repair, but repair completeness and cost remained inconsistent;
- model-authored submission review could find a defect yet fail to alter
  finalization, and broader reviewers missed most known violations;
- fresh exact phase reentry preserved continuity in code and research work,
  with domain-dependent call/token economics; and
- reserved handoff made selection reachable and transfer exact, but did not
  produce a bounded action-ready working set.

This stopped redundant readiness-reflection and phase-reentry experiments.

Evidence: [prior-evidence reconciliation](audits/NEXT_ROUTE_PRIOR_EVIDENCE_RECONCILIATION.md).

#### 24. Cross-study information-economics ledger

The offline ledger normalized 29 unique boundary×condition episodes from 12
pinned objects across acquisition, construction, repair, review, and closure.
It declared 11 within-boundary comparisons and did not pool incompatible task
scores.

It found no global representation winner. The strongest stable layer was exact
custody, pressure detection, reserve preservation, and minimum relief. It
selected one remaining distinct question: could a guaranteed maintenance-only
call choose a better workspace than the mechanical incumbent?

Evidence: [episode analysis](analysis/INFORMATION_ECONOMICS_REPORT.md).

### Phase 7 — dedicated maintenance and branch closure

#### 25. Maintenance eligibility

Both authentic pending-result boundaries could support a 512-token dedicated
manager with +2,784 and +3,863 headroom. The choice was nontrivial: seven and
three distinct single-result releases could make the ordinary packet feasible.
This qualified a selection experiment without spending GPU calls.

Evidence: [eligibility audit](audits/DEDICATED_MAINTENANCE_ELIGIBILITY.md).

#### 26. Dedicated workspace maintenance

Both managers returned syntactically valid, mechanically feasible release
sets. The pending results entered both actor invocations. Selection quality was
locally negative:

| Seed | Required relief | Manager removed | Actor headroom | Immediate actor action |
|---:|---:|---:|---:|---|
| 42 | 394 | 6,527 | +6,133 | request released source-navigation RESULTS |
| 314159 | 1,045 | 6,956 | +5,911 | request released source-navigation RESULTS |

The managers preserved 0/2 incumbent next decisions, and both actors
immediately requested the same released object. Four calls cost 72,599
serialized tokens. Reopens were requested but not executed because the actor
endpoint was one decision.

Dedicated mode solved reachability and feasibility. It did not make Qwen a
useful one-shot cache allocator. This closed open-ended model-owned eviction as
the current route without claiming universal impossibility.

Evidence: [dedicated-maintenance result](https://github.com/ScrappyTom/qwen38-dedicated-workspace-maintenance-v0/commit/44bade979d0ba1f1a2df3f2c919146c29d4c6868).

## Failure migration across the program

The sequence is best understood as one moving boundary:

```text
poor navigation
    -> structural addressability improves acquisition

all governing evidence acquired
    -> context cannot admit the next observation

minimum exact-body demotion
    -> next observation enters

recurrent demotion
    -> trajectory remains alive

longer horizon
    -> demote/reopen churn and chronology growth

fresh exact reentry
    -> construction becomes possible in one seed

short continuation
    -> effect/observation delivery fails again

exact-state recomposition
    -> updates cross boundaries

standing exact state
    -> resident rereads and update displacement

directories and exact focus
    -> demand relocates

semantic digest
    -> related demand expands, then original demand returns

progress state
    -> acquisition stops, but closure is premature

model-owned maintenance
```

## What the program did not establish

The sequence does not support any of these claims:

- Qwen never knows what information it needs;
- every reopen is irrational;
- the outline was semantically unnecessary;

## 27. Fresh-task whole-method scout: the policy did not activate as intended

The first fresh-task scout ran 71 actor calls across two tasks, two seeds, and

completion count. No prompt exceeded 9,948 tokens against an approximately

Treatment only performed scheduled fresh reentry at fixed call boundaries.

That scheduled operation reduced prefix-cache reuse in every pair and clearly
harmed code seed 42: control tested, repaired, retested, and submitted a passing
candidate; treatment entered verification with a stale failure and newer effect
present as separate exact objects, rewrote again, and ended with a passing but

Research geometry was weak: nine calls had to cover multi-source acquisition,

```text

named phase != reason to reset context
fresh reentry cost = tokens + lost cache + continuity risk
```

Scheduled low-occupancy reentry is retired. Earlier positive evidence for
pressure-triggered first-fit relief is unchanged because the scout never invoked
it. The successor must freeze an authentic prospective result-overflow boundary
and compare from that exact fork.

## 32. Ingress × bounded semantic work: active interaction without artifact work

The run completed in frozen order with 98 actor calls, 40 work-maintenance
calls, and 2,112,973 serialized tokens. Multi-range ingress activated in I2/I4,
and I3/I4 accepted 38 bounded replacement work records. Every configuration
nevertheless ended on the identical nine-word initial candidate: zero
mutations, effect-uptake decisions, checks, or submissions.

Batching improved ranges per accepted read decision, but its larger exact
results accelerated residency turnover. Both batch configurations reached the
two-reentry ceiling, and each later acquired three exact reopens. Batching was
therefore simultaneously an ingress-bandwidth change and a residency-pressure
change.

The maintenance actors generated real cross-source prose. I3's work record
eventually reached 13 source IDs over its lifetime; I4 also cited 13 and saw all
14 sources. Repeated bounded replacement did not preserve that breadth. Both
final records cited only four sources, and one I4 rewrite dropped every prior
citation. Mechanical provenance lists survived, but the relationships they
named did not necessarily remain in the prose.

The decisive design distinction is that this "cumulative work" was a lossy,
non-authoritative semantic sidecar. It was not a versioned partial charter,
requirement/evidence matrix with task semantics, or section artifact whose
effects could be taken up and checked. The actor still had to jump from
evidence plus sidecar to one complete 1,800–2,000-word charter replacement.
That transition never occurred.

The frozen post-run audit found one I1 negative-savings relief event: a receipt
for a one-line result increased the prompt by 79 tokens before the next
substitution restored feasibility. I1 remains sealed descriptive evidence,
I2–I4 remain mechanically qualified local negatives, and the full factorial is
censored. Successor relief must scan only prospectively rendered strictly
positive-savings substitutions.

This is the first measured interaction result, and it moves the program beyond
asking whether semantic state can be emitted. Both ingress and interpretation
were active. What failed was their coupling to durable, exact, independently
checkable task work and the action/feedback loop.

The next selected work is an offline Stage 0 for semantic integration × exact
incremental task-artifact externalization × version-bound verification and
repair under live ingress and common host-owned capacity safety. It is a
whole-system contrast, not isolated note, patch, or checker qualification. See
`E40_INGRESS_WORK_INTERACTION_RESULT.md` and
