# Mechanical pressure baseline v1

Date: 2026-08-24
Status: evaluated reference instrument; not the active architecture or research route

## Correction from v0

The fresh-task scout did not exercise pressure relief. Every prompt remained
below 10,000 tokens against an approximately 21,000-token prompt allowance.
Treatment activated only scheduled call-count reentry, which solved no current
capacity problem, reduced cache reuse in every pair, and disrupted one
qualified code trajectory.

V1 therefore removed scheduled phase reentry and retained the pressure
mechanism supported by earlier local experiments. That mechanism has since been
exercised on a fresh pressure-qualified Ceiba task.

## Reference policy

```text
exact external custody and access
+ ordinary chronology while healthy
+ host-owned response and named control reserves
+ on authentic prospective result overflow:
     prospectively render each exact-body→receipt candidate
     skip substitutions with zero or negative token recovery
     deterministic first-fit relief among positive-savings candidates
       under a frozen scan order
     and immediate stop at feasibility
+ exact reopen on actor demand
+ reactive exact reentry only if the declared relief class is insufficient
  or a prospectively declared external authority/world transition requires it
+ candidate-bound observation currency
+ hard call/token/time ceilings
```

The host owns exact custody, version/hash binding, token accounting, reserves,
prospective receipt-cost calculation, receipt substitution, and admission. The
actor supplies ordinary task decisions and actual read/reopen demand. No model
manager predicts the whole working set in this reference condition.

## Reentry admissibility

Reentry is not triggered by phase name, call count, apparent confusion, or host
judgment that construction should begin. A packet may contain only exact common
task/authority inputs, exact current candidate/world, the pending update that
caused the transition, exact information already delivered to that actor, a
predeclared mechanical causal tail, and exact handles.

It may not introduce investigator-selected useful evidence or semantic
relevance unavailable to control.

## Diagnostics and currentness

Raw tool output is preserved exactly. A task-specific deterministic
model-visible projection may omit prospectively declared volatile transport
fields while retaining stable criterion IDs/statuses, readiness, blocking
requirements, candidate binding, and a raw-result handle.

Each check is bound to the candidate/world version it evaluated. After a later
effect, the host may state mechanically that the earlier check is stale and
that the current candidate has not been verified by it.

## Excluded from this baseline

Scheduled reentry, semantic notes, digests, progress-state cues, model-owned
eviction, host relevance scoring, automatic phase detection, and learned
routing remain excluded from this mechanical baseline. This is not a program-
wide judgment that those arrangements can never be useful. Discovery probes may
test them when an independently motivated capability question requires the
contrast.

## Measured disposition

At the fresh Ceiba pressure boundary, deterministic first-fit relief admitted
the pending result and repeatedly preserved prompt feasibility. In each 18-call
continuation, ten later pressure events required sixteen substitutions and
80,497 cumulative recovered prompt tokens. The actor continued through novel
source ranges without exact reopen churn.

No mutation, check, submission, or artifact improvement occurred. Required
evidence remained incomplete and the actor-call budget, not context capacity,
ended the run. Seed 314159 v2 is the separately qualified primary cell and
aggregate. Seed 43's action/lifecycle history is post-freeze replay-qualified,
while its primary v1 cell and aggregate remain sealed-aborted. The two histories
produced the same model-facing trajectory at one donor boundary; they are not
independent task replications.

The result qualifies the policy's narrow use as a mechanical pressure and
observation instrument. It does not qualify it as a complete working-state or
task-performance architecture and does not select a longer receipt-only
continuation.

E40 subsequently exposed an apparatus correction to the eligibility law. One
I1 one-line exact observation was technically custodied and marked eligible,
but its rendered receipt increased the prompt by 79 tokens. The following
substitution restored feasibility, so the literal trajectory continued; the
first operation was nevertheless not relief and censors the full E40 matrix.

The corrected baseline therefore defines eligibility by the complete
prospectively rendered prompt delta, not object class alone. Equal- or
negative-savings substitutions remain exact-resident. If no positive candidate
can preserve the frozen reserves, the runtime follows its predeclared reactive
reentry or terminal path. This is a mandatory safety correction, not a new
eviction optimization branch.

## Claim bound

This is a pressure-response comparator, not a complete agent architecture.
Use it when a discovery or confirmation question genuinely activates result-
delivery pressure. Do not require every capability probe to occur at a pressure
boundary and do not optimize this policy by default.
