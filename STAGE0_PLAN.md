# Northstar transfer Stage 0 plan

## Purpose

Qualify a fresh whole-system interaction comparison without turning offline
geometry into behavioral evidence. Stage 0 freezes the world, comparator,
evaluation, budgets, transport, lifecycle, and stop rules. A separate ordinary
actor screen must still establish authentic pressure and a viable interaction
trigger.

## 1. Fresh task/world custody

The Northstar migration world is deterministic synthetic evidence, not a
relabeling of the earlier bounded-context research corpus. Fourteen exact
sources are materialized from `tools/materialize_transfer_world.py` and bound
by `task/TASK_SOURCE_LOCK.json`.

The task requires two inspectable artifacts:

1. a requirement-indexed evidence-integration ledger; and
2. a 1,500–2,100-word migration architecture decision.

The source corpus is deliberately larger than the context window, but that
fact only establishes possible large-world geometry. It does not qualify
pressure or treatment activation.

## 2. Viable comparator

`D0_DETACHED` and `A1_COUPLED` receive the same exact world, task, actions,
model/runtime, prompt limit, relief rule, maintenance instruction and budget,
reopen path, reentry rule, evaluator, and trajectory budgets.

Their only prospective difference is feedback topology:

- detached maintenance remains a non-authoritative sidecar;
- coupled maintenance mutates the required ledger file and emits an exact
  candidate effect.

Provider-free fixtures must prove both systems can traverse the same complete
loop. The coupled ledger remains actor-revisable; maintenance is neither
authoritative nor immutable.

## 3. Authentic interaction activation

The frozen screen runs one ordinary chronology with no treatment mechanism.
It may select a fork only when a pending source observation itself makes the
next prompt exceed 20,992 tokens after at least four prior source observations
were delivered, while the candidate remains initial and no check or submission
occurred.

The offline post-run audit must rerender the exact packet and show that at least
one prior exact-backed source result can be replaced by a strictly smaller
receipt. The pending result is protected. A pressure event with no positive
relief candidate is non-diagnostic for this comparator.

Actor decisions may diverge only after the common boundary. Neither reentry nor
maintenance may inject an investigator-selected source that did not cross that
arm's model boundary.

## 4. Candidate-bound evaluation and readiness

The mechanical evaluator binds every result to the exact ledger-plus-decision
composite hash. Checks become stale after any candidate effect. Stable
model-visible diagnostics exclude volatile fields while exact raw output stays
in custody.

Independent condition-blinded semantic adjudication uses frozen R01–R12
criteria. `ready` requires:

- the mechanical precheck;
- all twelve semantic criteria met;
- no unsupported claim or forbidden shortcut;
- no unresolved blocking requirement; and
- a current candidate-bound final check.

Submission is a proposal, not evidence of readiness.

## 5. Event-contingent completion budget

Each measured configuration receives up to 22 actor calls to cross a frozen
mechanical construction milestone. If it never crosses, the terminal result is
`construction_milestone_not_reached`.

Crossing the milestone grants exactly eight additional actor calls. The clean
minimum path is four decisions:

1. receive the construction effect and run a check;
2. receive the check and repair;
3. receive the repair effect and recheck; and
4. receive the current recheck and propose closure.

The remaining four calls are a prospectively equal allowance for targeted
additional repair or action-expression loss. They are not granted based on
outcome. The milestone itself carries `semantic_readiness: not_adjudicated`.

## 6. Provider-free qualification

The full fixture must exercise, in both configurations:

`pressure -> positive relief -> maintenance -> actor uptake -> candidate work`
`-> effect uptake -> check -> repair -> stale prior check -> current recheck`
`-> closure proposal`

It must also produce a candidate that passes every frozen mechanical criterion
and therefore awaits, rather than bypasses, independent semantic adjudication.

## 7. Execution ladder

1. Offline Stage 0: task/world, contracts, fixtures, tests, and preflight.
2. Explicitly authorized 18-call ordinary pressure screen.
3. Offline exact screen audit and boundary-handoff commit.
4. Regenerated measured preflight against that exact fork.
5. Separate explicit authorization for the two-configuration measured run.
6. Candidate-hash-blinded semantic adjudication and exact readiness ledger.

No step authorizes the next. A non-diagnostic screen ends this task selection;
the task is not rewritten after observing its trajectory.
