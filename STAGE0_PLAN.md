# Cedar ingress-aligned transfer: offline Stage 0 plan

## Purpose

Select a fresh task in which authentic interaction activation is physically
reachable under the exact action geometry the actor is allowed to use. Stage 0
freezes task/world custody, ingress, activation, comparator, evaluation,
budgets, runners, fixtures, and stopping rules. It does not infer that the live
actor will follow the rendered path and does not authorize inference.

## 1. Correction carried forward

The Northstar screen exposed a unit mismatch:

`batch action -> one result object -> several source observations`

while eligibility required four result objects. The new rule uses an invariant
below transport packaging: exact delivered source-line coverage. It remains
meaningful for single reads, two-range batches, split reads, and overlapping
reads.

For every source, the catalog freezes an evidence domain and
`activation_min_lines = 55`. The gate is:

1. at least four source IDs have at least 55 unique delivered lines;
2. those sources span at least three frozen domains;
3. the pending source observation contains a novel line;
4. the candidate remains exact-initial;
5. no check or submission occurred;
6. its addition makes the next prompt exceed 20,992 tokens; and
7. a protected-pending, strictly positive first-fit substitution can restore
   feasibility.

The host performs interval union and catalog lookup only. It does not judge
which facts matter or whether acquisition is “enough.” Pressure before this
gate is a frozen non-diagnostic endpoint, not permission to resize sources or
retry. Domain and threshold fields are held in the host-side source lock and
omitted from the actor-facing catalog so the screen does not cue the model to
optimize for experimental eligibility.

## 2. Fresh task/world

Cedar Valley is independent of the prior research, navigation, migration, and
code tasks. Sixteen exact synthetic sources must be integrated into two
inspectable artifacts. The sources are individually small enough for either
permitted ingress form, but collectively exceed the context window. The task
requires coupled reasoning across authority, hazards, demand, routes, fleet,
shelter, medical needs, communications, continuity, animals, privacy,
exercise evidence, costs, weather, and readiness.

The generator and active task lock make freshness and exact custody auditable.
The old repository sources are not in `task/SOURCE_CATALOG.json` and cannot be
requested through the action interface.

## 3. Prospective geometry qualification

Stage 0 enumerates every full single and every full two-source pair through the
same world wrapper and tokenizer used by the runners. It rejects Stage 0 if any
declared full-source ingress exceeds the source-result cap.

It also renders a complete synthetic chronology with ordinary actor actions
and exact wrapped observations. This must demonstrate both:

- the maturity gate fits after two admissible batches; and
- a later admissible result can create pressure with positive first-fit relief.

This is a reachability proof, not a claim about realized actor behavior.

## 4. Viable whole-system comparator

`D0_DETACHED` and `A1_COUPLED` share all functions except the feedback topology
of accepted semantic integration. In D0 it is a resident sidecar; in A1 those
same bytes become exact candidate work and produce a candidate effect. In both
arms the actor may revise the work, exact sources remain reopenable, checks bind
to candidate versions, and readiness is externally adjudicated.

The comparison preserves the interaction among ingress, residency, semantic
persistence, work-product persistence, effects, verification, repair, and
closure. It does not hold those downstream functions inactive to isolate a
component.

## 5. Candidate-bound evaluation

The mechanical evaluator freezes exact title, headings, length, source breadth,
ledger coverage, and a small set of deterministic term gates. Passing it does
not mean the plan is safe. The separate R01–R12 protocol evaluates the coupled
relationships and blocks readiness unless every criterion is met, no forbidden
shortcut or unsupported claim remains, and a current candidate-bound check
exists. Condition labels are masked where feasible.

## 6. Decision and maintenance budgets

Per measured configuration:

- 26 preconstruction actor decisions;
- eight decisions after the mechanical construction milestone;
- 34 actor decisions maximum;
- 18 maintenance calls;
- two reactive reentries;
- 1,600,000 serialized tokens;
- 10,800 wall-clock seconds;
- one attempt per call and zero retries.

The clean postconstruction path consumes four decisions: check, repair, recheck,
and closure after the relevant effects cross actor boundaries. Four extra
decisions are frozen for further repair or expression loss. A construction
milestone grants time only and carries no readiness authority.

## 7. Provider-free qualification

Fixtures must exercise both feedback systems through:

`pressure -> positive relief -> semantic maintenance -> actor continuation`
`-> exact artifact work -> effect uptake -> check -> repair -> stale binding`
`-> current recheck -> closure proposal -> external mechanical evaluation`

The full dry run must produce an evaluator-complete candidate in both arms,
while leaving semantic readiness pending. This validates plumbing and budgets,
not behavioral utility.

## 8. Execution ladder

1. Finish and commit offline Stage 0.
2. Obtain explicit authorization for the 20-call ordinary Cedar pressure screen.
3. Run once with no relief, maintenance, coupling, or reentry.
4. Audit exact custody, line/domain activation, pending novelty, tokenizer count,
   and positive relief offline.
5. If eligible, commit the boundary and regenerate the measured preflight.
6. Obtain separate authorization for the two-arm measured continuation.
7. Run both arms regardless of first-arm outcome unless apparatus or safety fails.
8. Freeze candidate-hash-blinded semantic adjudication and readiness.

No step authorizes the next. A non-diagnostic screen closes this task selection.
