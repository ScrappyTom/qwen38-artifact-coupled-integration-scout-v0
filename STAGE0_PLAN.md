# Stage 0 plan

## 1. Reconstruct the donor gap

Bind the E40 result exactly and show, for every accepted maintenance output:

- where the semantic bytes lived;
- whether they changed the task candidate;
- whether an effect crossed a later actor boundary;
- whether any check evaluated those bytes; and
- whether the final candidate incorporated them.

This is an offline donor audit, not a historical control arm.

## 2. Qualify the pressure substrate

The relief selector must prospectively render each candidate receipt in the
complete current packet. It may externalize only a result whose replacement
strictly lowers prompt tokens. It scans oldest-first among those positive
candidates and stops immediately when the pending packet is feasible.

Required fixtures cover:

- receipt larger than body;
- receipt equal to body;
- skipped non-positive candidate followed by a positive candidate;
- no positive candidate;
- maintenance growth after a positive substitution; and
- pending-result protection.

## 3. Qualify the fresh task geometry

The task uses a new task version and a fresh candidate, while its sources are
exact program documents pinned to their donor commit and Git blobs. Stage 0
must calculate a plausible successful path including acquisition, at least one
integration update, exact effect uptake, decision construction, current check,
repair allowance, and closure. Total accessible world size alone is not an
activation argument.

## 4. Qualify parity and non-oracularity

Both configurations have the same task, source catalog, evidence permissions,
ordinary actor actions, model/runtime, and resource ceilings. Actor-requested
observations may diverge. Maintenance may use only exact observations already
delivered to that arm plus its prior accepted integration state. Reentry may
not add investigator-selected evidence.

## 5. Qualify the complete provider-free loop

Fixtures must execute:

`read -> deliver -> pressure relief -> maintenance -> actor-visible uptake ->`
`candidate effect (A1 only) -> incremental section effect -> check -> stale`
`after repair -> current recheck -> submit`

The detached fixture must prove that its sidecar does not silently mutate the
candidate. The coupled fixture must prove that maintenance does.

## 6. Live execution ladder

1. Maintenance-expression qualification: one initialization and one update
   case per configuration family; no task actor.
2. One matched exploratory trajectory per configuration if expression passes.
3. Independent condition-blinded artifact adjudication.
4. A second frozen seed only when the first comparison is mechanically valid
   and interpretable, including valid negative or harmful outcomes.

Each live tranche requires a new frozen commit and explicit GPU authorization.
