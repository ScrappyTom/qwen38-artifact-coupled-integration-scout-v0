## Reading conventions

* **Visible** names the important model-facing exact or semantic state, not every
  repeated task/schema token.

  action and is labeled accordingly.

maintenance calls. That common trajectory is described once. Only the

## Integrated interpretation

The comparison exposes a lifecycle tradeoff rather than a winning memory format:

```text
retain scaffold + append full verification path
    preserves history
    but exhausts model-facing capacity before repair

demote scaffold + replace with current verification state
    enables check, evidence, repair, effect uptake, recheck
    but loses recurrence-sensitive causal continuity
```

The likely target is a bounded current-state frame with a small exact mechanical
causal tail, not a return to indefinitely resident chronology and not a new
freeform global note. The needed information is concrete and host-derivable:

* latest attempted action and admission/rejection;
* latest delivered result/effect and applicable candidate version;
* current check and currency;
* repeated identical action/object count;
* whether those repeats changed candidate or check;
* exact handles to the displaced path.

That hypothesis remains untested. The present run establishes only that P1's
whole lifecycle allocation improved repair opportunity and candidate quality,
then failed in a repeat-read control loop.
