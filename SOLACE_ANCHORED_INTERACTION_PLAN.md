# Solace fault-tolerant anchored-provenance interaction plan

Date: 2026-08-26

Status: offline design; GPU execution requires a new frozen commit and explicit
authorization

## Question

At the exact Solace pressure fork, does a fallible provenance-local semantic
register improve cumulative exact task work and useful completion relative to
direct exact work alone?

This is an interaction experiment. It does not isolate carrier expression. It
follows pressure relief, semantic transformation, induced actor demand,
artifact mutation, effect uptake, checking, repair/recheck opportunity,
submission, independent readiness, and total cost.

## Configurations

### W0_DIRECT_EXACT_WORK_FRESH

Exact custody, ordinary actor chronology, protected-pending deterministic
first-fit relief, exact reopen, the task-native evidence ledger, incremental
decision sections, effects, candidate-bound checks, repair, recheck, and
submission proposal.

### L1_FAULT_TOLERANT_ANCHORED_PROVENANCE

The complete W0 system plus a separately charged semantic-maintenance call for
newly externalized source observations.

The model owns semantic selection:

- source slot and exact version;
- assertion mode;
- referents;
- one bounded statement; and
- one exact unique single-line anchor substring.

The host owns exact provenance serialization:

- anchor bytes and byte offsets;
- containing-line context;
- hashes;
- result/source/version binding;
- currentness; and
- exact reopen custody.

Claims are admitted independently. Invalid claims are discarded without repair
or retry. A zero-valid output leaves the prior register unchanged. A valid
subset is merged. Ordinary actor work always continues unless the separately
frozen resource budget or a genuine apparatus failure stops the trajectory.

The register is incomplete, non-authoritative, bounded, and actor-visible. It
cannot authorize readiness or replace exact verification. Cross-source
synthesis remains exact task work in both arms.

## Lifecycle

```text
audited common pressure fork
        ↓
protected-pending first-fit relief
        ↓
L1 only: one fallible maintenance call over each newly externalized
source observation; partial admission and unchanged-state fallback
        ↓
pending exact result crosses the next actor boundary
        ↓
ordinary reads / reopens / exact incremental artifact work
        ↓
effects cross later actor boundaries when calls remain
        ↓
candidate-bound check / repair / recheck / submission opportunity
        ↓
independent candidate-bound evaluation and information-economic audit
```

Any register growth participates in the next full prompt-feasibility decision.
It may induce further exact externalization and further maintenance. That
feedback is part of the treatment, not hidden overhead.

- at most 34 actor calls per cell;

The construction milestone grants calls but is not quality or readiness.
Budget exhaustion records the exact unresolved state; it does not force
submission or add another semantic mechanism.

## Primary outcomes

Report separately:

- exact final artifact quality and criterion-level findings;
- correct closure/readiness;
- candidate effect uptake;
- current check and repair/recheck behavior; and
- useful completion.

Useful completion requires a frozen-ready artifact and appropriate closure; a
faster false closure is a loss.

## Claim limit

A treatment win would support this complete L1 configuration in this Solace
state. It would not prove that every claim, carrier field, or maintenance timing
choice is necessary. A treatment loss would not establish that all semantic
persistence is useless. The first genuinely new system failure should route any
successor.
